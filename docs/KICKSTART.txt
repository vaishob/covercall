**Exit check (§13.2):** journeys **J2 (cascade)** and **J3 (escalation)** run end to end on Cloud Run in `asia-southeast1` with simulated personas, driven from a text-only test page. Every transition appears in `gaps/{gapId}/events`, and `verify_chain(gapId)` passes.

### 4.1 Firestore schema and the tamper-evident event chain (implement in `services/api/app/events.py`)
- Collections follow §8.1 exactly: `gaps`, `gaps/{gapId}/events/{seq}`, `plans`, `offers`, `approvals`, `quarantine`, `shifts`, `ledgers`, `staff`, `outlets`. The `sim` database holds `personas`.
- The gap document carries `state`, `version`, `last_seq` and `last_hash`, plus every §8.1 field.
- Event document ID is `seq`, zero-padded to 6 digits (`000001`). Fields: `seq, type, from_state, to_state, actor (lead | system | staff:<id> | model:<id>), model_ids[], rule_ids[], trace_id, payload (redacted), prev_hash, hash, ts, synthetic`.
- **Hash rule:** `canonical = json.dumps(event_without_hash, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")`, then `hash = sha256(prev_hash.encode() + canonical).hexdigest()`. The genesis `prev_hash` is `"0" * 64`.
- **Append is one Firestore transaction:** read the gap; assert the expected `version` and that `(from_state, type)` is in the transition table; write the event; update `state`, `version + 1`, `last_seq` and `last_hash` atomically. A version mismatch raises `commit.conflict` handling. A transition not in the table raises an error. **Any transition not in the table is a bug.**
- Encode the full §5.1 transition table as a single constant `TRANSITIONS` (from-state, event, to-state), shared by the append guard and the tests.
- `redact(payload)` runs **before** every write: NRIC/FIN pattern, Singapore phone numbers (optional +65), emails, and 13–19 digit card-like numbers. PII must never reach events, logs or traces (`pii_leak` is P0).
- `verify_chain(gap_id) -> ChainReport` recomputes every hash. Tests cover a clean chain, a tampered payload, a deleted event and a reordered event.
- **Idempotency:** every inbound reply carries a `message_id`. `api` drops duplicates (a transactional create of a dedup doc) before resuming any workflow.
- Firestore security rules: clients get **read-only** access scoped to the demo tenant, and no client writes. Only the `persona-sim` service account can read the `sim` database. The planner and solver service accounts have no access to `sim`.

### 4.2 `api` service (FastAPI, Cloud Run)

### 4.3 `policy/timing.py` (pure functions, unit-tested; §5.2)
`mustFillBy(c) = shiftStart − travel(c) − buffer`; `slack(t) = max_c mustFillBy(c) − t`; `replyWindow(t) = min(w_max, max(w_min, slack(t)/k))`. A candidate is viable iff `t + replyWindow(t) ≤ mustFillBy(c)`. Fan out to the top `fanout_n` when `slack(t) < fanout_threshold`. `t_esc = max_c mustFillBy(c) − escalationLead`, or immediately when no viable candidate remains. All times are ISO 8601 with `+08:00`.

### 4.4 `workflows/coverage_cascade.yaml` (Cloud Workflows; the only state owner)
Implement the §5 state machine: `REPORTED → GUARDED → SOLVED → OUTREACH`, then `COMMITTING → FILLED`, `ESCALATED → RESOLVED`, `HELD`, `CANCELLED`. Every step that changes state calls `/internal/transition` first.
- All service calls use `http.post` with `auth: {type: OIDC}` and a retry policy with exponential backoff and at most `retry_attempts` (3). The **guard step has no retry-to-pass**: any exception routes to `guard.unavailable → HELD`.
- **REPORTED:** call `guard`. A flag or error → `HELD` (lead notified, nothing sent to staff). `ok` + complete parse → `input.guarded → GUARDED`. Missing fields → one clarifying question to the lead.
- **GUARDED:** call `/internal/solve`. Validator agrees on every ranked candidate → `plan.solved → SOLVED`. Any disagreement → `plan.disagreement → HELD` (P0).
- **SOLVED:** create a callback endpoint for the approval and await it. `plan.approved` → `OUTREACH` (approval stored, escalation strategy locked). `plan.rejected` → `GUARDED` with the lead's new constraint.
- **OUTREACH (durable waits):**
```yaml
  - create_cb:
      call: events.create_callback_endpoint
      args: { http_callback_method: "POST" }
      result: cb
  - register_offer:   # api stores cb.url server-side in offers/{offerId}; sends the offer only if a covering T2 approval exists
      call: http.post
      args: { url: ${api_url + "/internal/transition"}, auth: { type: OIDC }, body: { ... } }
  - wait_reply:
      try:
        call: events.await_callback
        args: { callback: ${cb}, timeout: ${reply_window_s} }
        result: reply
      except:
        as: e
        steps:
          - is_timeout:
              switch:
                - condition: ${"TimeoutError" in e.tags}
                  next: on_offer_timeout     # → offer.timeout
          - rethrow: { raise: ${e} }
```
  Each callback resumes with `{offer_id, message_id}` only. The workflow then calls `guard` (flag → `reply.flagged`: quarantine for lead review, skip that candidate) and `agent` `parse_reply` (§7.3 schema). It branches `reply.accept` → `COMMITTING`, `reply.decline`/`offer.timeout` → next offer or fan-out, or `reply.counter` → re-solve (back to `SOLVED` only on a material change: time shift >30 min or cost up).
- **Fan-out:** when slack falls below the threshold, send the top `fanout_n` offers against one callback endpoint and loop on `events.await_callback` until the first valid accept, all decline, or timeout. Verify in the Workflows callbacks docs that one endpoint can receive multiple requests. If it cannot, use a `parallel` block with one endpoint per offer and a shared `winner` variable. Record which you used.
- **Escalation:** at `t_esc`, or immediately when no viable candidate remains → `escalation.due → ESCALATED`. Notify the lead with ranked fallbacks (borrow, reduced service, lead covers, agency, unfilled) and await `fallback.chosen → RESOLVED`. Escalation MUST never fire after `t_esc` (`escalation_late` is P0).
- **COMMITTING:** `api` runs a Firestore transaction on the gap's `version` with a validator re-check inside it. `commit.ok → FILLED` (roster updated, one-sentence summary, `cost_saved_sgd` recorded). `commit.conflict → OUTREACH` with a courtesy reply to the late candidate. Other open offers get courtesy withdrawals.
- `gap.cancelled` from any state → `CANCELLED`, with open offers withdrawn.
- Every gap MUST end in a recorded terminal outcome (`outcome_missing` is P0).
